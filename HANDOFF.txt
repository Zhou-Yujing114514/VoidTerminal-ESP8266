本文档用于工作交接，记录对 VoidTerminal-ESP8266 项目的全部认识与见解。
接手方：豆包。日期：2026-09-06。

------------------------------------------------------------

一、项目是什么

一个跑在 ESP8266 墨水屏上的"虚空终端"设备固件，功能包括：

1. 虚空终端聊天：连接 buer.kdns.fr 的聊天站，支持公屏/群聊/私聊，九宫格(十二宫格)中文输入法
2. 服务器监控：HTTP 轮询两台服务器的运行状态（CPU/内存/磁盘等）
3. 时钟
4. 配网系统：AP 热点 + Web 配网页，配置 WiFi 和聊天账号（存 EEPROM）

硬件平台
- ESP8266（ESP-12F），4MB Flash，DIO 模式，80MHz
- 2.9 寸墨水屏（296×128，GxEPD2 驱动）
- 3 个按键：MENU/UP/DOWN；注意 UP=GPIO3（RX 引脚，SD 卡版阅读器），GPIO0 与 EPD_DC 冲突需 readPinSafe 临时切模式
- 中文显示用 U8g2_for_Adafruit_GFX + wqy14 字体

构建平台
- PlatformIO（Arduino framework，board = nodemcuv2）
- 本地仓库路径：/tmp/opencode/VoidTerminal-ESP8266（开发机）
- 固件产物同步在开发机 /workspace/

二、服务器端架构（豆包已维护）

聊天站
- 域名 buer.kdns.fr，走 Cloudflare CDN，回源 Nginx(:80) → Node.js Express(:3000) + WebSocket(/ws)
- 应用目录 /opt/chat-app，systemd 服务 chat-app.service
- 后端 server.js（Node.js，ws 库做 WebSocket）
- 数据存 /opt/chat-app/data/*.json

聊天登录与 WebSocket 协议（已与豆包对齐）
- 登录：POST https://buer.kdns.fr/api/login，body {"username","password"}，返回 {"ok":true,"token":...,"user":{...}}
- WebSocket：wss://buer.kdns.fr/ws
- 认证消息：{"type":"auth","token":"xxx","lite":true} → 服务器回精简 hello（约 4.6KB，8 字段）
- 实时消息类型：global（公屏）、group（带 gid）、dm（带 to）
- 发送：公屏 {"type":"global","content":...}；群聊加 gid；私聊加 to
- 接收判断自己：from == 自己 userId
- 服务器有 verifyClient 校验 Origin，只放行无 Origin 或 https://buer.kdns.fr，其余 403

监控服务器
- cn-fj-qz-1.server.zakocloud.com，端口 51808（聊天站）/ 51809（小说站）
- NAT 平台共享公网 IP 120.33.34.156
- 端点 GET http://host:port/api/status，返回 JSON（cpu/memory/disk/network/process_count/uptime 等）
- 注意：服务器响应慢（2~7 秒），且 51808 偶发 404/403（NAT 平台拦截页）

服务器 SSH（豆包已持有）
- 地址 cn-fj-qz-1.server.zakocloud.com，端口 54188，用户 root（密码在环境变量 SSHPASS，用 sshpass 连接）

三、固件代码结构

  chat.cpp/h          聊天：登录+WebSocket协议+输入法+诊断屏
  monitor.cpp/h       服务器监控：HTTP轮询+双服务器切换
  wifi_config.cpp/h   WiFi预设+聊天账号(EEPROM)+配网AP
  display.cpp/h       墨水屏绘制+UTF-8换行
  font_flash_section.h 字体放flash的段定义(-include引入)
  input.cpp/h         按键检测(单击/双击/长按)
  app_state.cpp/h     状态机(菜单/聊天/监控/时钟/配网)
  clock.cpp/h         时钟
lib/WebSockets/       vendor化的WebSocket库(改了3处，见下)
platformio.ini        PlatformIO配置(含关键build_flags)

platformio.ini 关键 build_flags
-include src/font_flash_section.h   # 字体放flash
-DWEBSOCKETS_TCP_TIMEOUT=15000      # WS TCP超时
-DCONT_STACKSIZE=6144               # 主循环栈6KB(避免ECDSA验签栈溢出)

lib/WebSockets 三处改动（重要！）
1. WebSocketsClient.cpp 构造函数：默认 Origin: file:// → Origin: https://buer.kdns.fr（否则服务器 verifyClient 返回 403）
2. WebSocketsClient.cpp connect 处：setBufferSizes(6144, 512)（hello 加密 record 约 4.7KB，4KB 不够、8KB 爆堆崩溃）
3. WebSocketsClient.cpp connect 处：setTimeout(120000)（服务器发完 hello 后静默，默认 15s 会误断开）
4. 另加 sendPong 方法（收到服务器 ping 回 pong）

四、已解决的关键问题（根因分析，最有价值）

4.1 RAM 反复横跳（96.9%）
- 根因：中文字体数组落在 RAM 的 .rodata
- 解决：字体放 flash（font_flash_section.h 用带 name 的独立段 .irom.text.<name> + --gc-sections 只保留被引用的字体）

4.2 登录失败 / TLS 握手失败
- 根因：服务器只提供 ECDSA 证书（实测 ECDHE-ECDSA 系列 cipher 全 OK，RSA 系列全 FAIL）
- ESP8266 的 axTLS 不支持 ECDSA，必须用 BearSSL（本 core 版本 WiFiClientSecure.h 已是 BearSSL 别名，无需额外配置）
- ECDSA 是纯软件运算，握手慢，超时需 ≥15s（默认 5s 不够）
- 证书链约 2KB（叶子证书 DER 仅 899 字节）

4.3 崩溃（Hardware Watchdog）
- 根因：处理 hello 时内存峰值爆堆 —— payload(4.6KB) + TLS 缓冲 + JSON doc(8KB) ≈ 19KB，顶爆堆容量
- 解决：TLS 缓冲 6KB + 用 ArduinoJson filter 跳过 hello 里不重要的 globalMsgs 历史消息（实时会推送），doc 8KB→4KB
- 附：栈从默认 4KB 增大到 6KB（-DCONT_STACKSIZE=6144），避免 ECDSA 验签栈溢出

4.4 WS 握手返回 403
- 根因：WebSocket 库默认发送 Origin: file://，服务器 verifyClient 只放行 buer.kdns.fr，返回 403
- 解决：改库默认 Origin 为 https://buer.kdns.fr（setExtraHeaders 覆盖无效，必须改源头）

4.5 WS 反复断开重连
- 根因：服务器发完 hello + presence 后静默（实测 45 秒+无任何消息，也不发心跳 ping）
- BearSSL 默认读超时 15s，静默期误断开
- 解决：读超时 120s + 客户端主动心跳（每 20s 发 ping，服务器 ws 库自动回 pong）

4.6 服务器监控失败（当前遗留）
- 现象：51808 返回 404/403（NAT 平台拦截页），51809 返回 200
- 这是 NAT 平台（zakocloud）的映射问题，非固件问题，需要检查 51808 端口映射

七、构建与发布流程

1. 改代码 → git add + git commit + git push origin master
2. GitHub Actions 自动触发（build.yml）：pio run → 生成 firmware.bin + VoidTerminal-ESP8266_latest_4MB_DIO.bin（4MB 整包，用 0xFF 填充）
3. 手动打 Release：tag 命名 vYYYYMMDD-HHMM，上传两个固件资产
4. 用户刷 4MB 整包（VoidTerminal-ESP8266_latest_4MB_DIO.bin）

GitHub 操作要点
- Token：需向用户索取（用于 API 打 Release/上传资产/查 CI，此处不落盘）
- 敏感信息（WiFi 密码、账号密码）不要提交到 GitHub 公开仓库（已 force-push 清除过一次）
